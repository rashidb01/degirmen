# Degirmen — электронное меню и приём заказов

Сайт ресторана: цифровое меню с категориями, AI-помощник (аллергены, замена блюд, рекомендации)
и приём заказов прямо на сайте. Никакого мобильного приложения — чистый веб (HTML/CSS/JS +
Node/Express backend), без сборки/бандлера.

Это объединение идей двух прошлых Flutter-проектов (**Menu QR** — меню/QR/заказы, **chat_mate_app**
— AI-чат на Groq), переписанное с нуля под сайт.

## Структура

```
Degirmen/
  backend/           Node/Express сервер: API меню, заказов, AI-чата + отдаёт сам сайт
    server.js
    data/            "база данных" на JSON-файлах (бесплатно, без внешней БД)
      categories.json
      dishes.json
      orders.json
    uploads/          загруженные из админки фото блюд
    .env              секреты (ключ Groq, пароль админки) — НЕ в git
  public/             сам сайт (отдаётся статикой из backend)
    index.html         главная страница меню + корзина + чат
    admin.html          админ-панель (блюда, категории, заказы)
    css/, js/, assets/
```

## Запуск локально

```sh
cd backend
npm install
npm start          # http://localhost:4100
```

Сайт: `http://localhost:4100/`
Админка: `http://localhost:4100/admin.html` (пароль — значение `ADMIN_KEY` из `backend/.env`)

## Как добавить блюда (то самое "закину из интернета")

Зайти в `/admin.html` → вкладка **Блюда** → заполнить название, категорию, цену, описание,
аллергены и теги, и либо вставить прямую ссылку на фото, либо загрузить файл. Категории
редактируются на вкладке **Категории**.

## AI-чат-помощник

Кнопка снизу справа на сайте. Отвечает на вопросы про состав, аллергены, помогает выбрать
блюдо и предлагает замену — используя **только реальные данные из текущего меню** (никогда не
выдумывает блюда/цены/аллергены). Работает через Groq API (`backend/server.js`, `/api/chat`).

Ключ `GROQ_API_KEY` в `backend/.env` — тот же, что используется на продакшн-сервере
`chatmate.ink` (я его только прочитал по SSH, больше туда ничего не менял). При необходимости
смените модель через `GROQ_MODEL` в `.env` (по умолчанию `openai/gpt-oss-120b`).

## Заказы

Гость собирает корзину → указывает номер стола и комментарий (например, аллергии) →
"Оформить заказ" → заказ сохраняется на сервере и сразу виден в админке на вкладке **Заказы**,
где официант/менеджер меняет статус (Новый → Подтверждён → Готовится → Готов → Подан).

Оплата сейчас — **на кассе**. Онлайн-оплата не подключена.

## Что уже подготовлено, но пока не подключено (как договаривались — "потом")

- **R-Keeper**: в `backend/server.js` есть функция-заглушка `sendOrderToRKeeper(order)`,
  вызываемая при создании каждого заказа. Как только будут креды R-Keeper (StationAPI/RK7),
  туда добавляется реальный запрос — переделывать сам flow заказа не нужно.
- **Kaspi Pay**: в объекте заказа уже есть поле `payment: { method, status }`. Когда ресторан
  зарегистрируется в Kaspi Pay, здесь появится генерация ссылки/QR на оплату и вебхук статуса.

## Деплой

Сайт целиком (фронтенд + API) — один Node-процесс, значит деплой такой же, как у `chatmate.ink`
(смотри `chat_mate_app/CLAUDE.md` для примера): залить `backend/` и `public/` на сервер,
`npm install --omit=dev` в `backend/`, поднять через `pm2`, `.env` создать на сервере вручную
(он не в git).

```sh
cd backend && npm install --omit=dev
pm2 start server.js --name degirmen
```

## Переменные окружения (`backend/.env`)

См. `backend/.env.example`. Обязательные: `GROQ_API_KEY` (AI-чат), `ADMIN_KEY` (пароль админки).
